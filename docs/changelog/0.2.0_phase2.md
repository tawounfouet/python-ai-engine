# Changelog - Version 0.2.0 (Phase 2 : Storage Layer)

**Date** : Mars 2026

## Vue d'ensemble

Phase 2 introduit la couche de persistence entièrement découplée de tout ORM. Un contrat abstrait unique (`StorageBackend`) définit l'intégralité des opérations CRUD ; deux implémentations concrètes couvrent les cas d'usage les plus fréquents — tests en mémoire et usage local persistant.

---

## Ajouts ✨

### 💾 Interface abstraite (`src/ai_engine/storage/base.py`)

- **`StorageBackend` ABC** — Contrat de persistence complet :
  - Méthodes abstraites pour **11 entités** : Providers, Agents, Tools, Skills, AgentSkillAssignments, Conversations, Messages, Executions, ExecutionSteps, Graphs, AgentMemories, KnowledgeSources
  - Pattern CRUD uniforme par entité : `save_*`, `get_*`, `list_*`, `delete_*`
  - Méthodes de requête spécialisées : `get_agent_by_slug()`, `list_agents(role=, provider_id=)`, `get_conversation_messages()`, `list_conversations(agent_id=, status=)`, `get_latest_execution()`, `list_memories(agent_id=, memory_type=)`, `get_memory_by_key()`, etc.
  - `context_manager()` : gestionnaire de contexte optionnel pour les backends transactionnels
  - Toutes les signatures typées avec les modèles Pydantic de la Phase 1 — zero couplage Django

- **Contrat de filtrabilité** : tous les `list_*` acceptent des filtres optionnels typés (`is_active`, `role`, `status`, `agent_id`, etc.) garantissant la cohérence entre backends

### 🟢 `InMemoryStorage` (`src/ai_engine/storage/memory.py`)

Implémentation légère, zero-dépendance, idéale pour tests et prototypage :

- **Stockage interne** : 12 dictionnaires Python (`_providers`, `_agents`, `_tools`, `_skills`, `_skill_assignments`, `_conversations`, `_messages`, `_executions`, `_execution_steps`, `_graphs`, `_memories`, `_knowledge_sources`)
- **Fidélité totale au contrat** : implémente les 60+ méthodes abstraites de `StorageBackend`
- Opérations `save_*` : upsert par `id` avec mise à jour du timestamp `updated_at`
- Opérations `list_*` : filtrages Python natifs sans SQL
- `clear()` : réinitialisation complète (utile entre tests)

### 🗄 `SQLiteStorage` (`src/ai_engine/storage/sqlite.py`)

Implémentation persistante zero-config, fondée sur `sqlite3` stdlib :

- **Stratégie hybride colonnes + JSON** : chaque entité est stockée en JSON sérialisé dans une colonne `data`, avec des colonnes indexées séparées pour les requêtes fréquentes (`id`, `slug`, `agent_id`, `status`, `key`, etc.)
  - Avantage : flexibilité schemaless + vitesse des index SQL
- **Création automatique des tables** au premier accès (`CREATE TABLE IF NOT EXISTS`)
- **12 tables** créées automatiquement : `providers`, `agents`, `tools`, `skills`, `skill_assignments`, `conversations`, `messages`, `executions`, `execution_steps`, `graphs`, `memories`, `knowledge_sources`
- **`_serialize(model)`** / **`_deserialize(cls, data)`** : conversion bidirectionnelle Pydantic ↔ JSON string via `model_dump_json()` / `model_validate_json()`
- **`@contextmanager connection()`** : gestion sûre des connexions SQLite avec commit/rollback automatique
- Support du mode `:memory:` pour les tests (fichier temporaire en RAM)
- **Sérialisation des `SecretStr`** : les clés API sont sérialisées via `get_secret_value()` et restaurées à la désérialisation

## Fiabilité 🧪

- **7 fichiers de tests** dans `tests/unit/storage/` et `tests/integration/` :
  - `test_base_storage.py` / `test_base_storage_fixed.py` — validation du contrat ABC
  - `test_memory_storage.py` / `test_memory_storage_fixed.py` — couverture complète `InMemoryStorage`
  - `test_sqlite_storage.py` / `test_sqlite_storage_fixed.py` — couverture complète `SQLiteStorage`
  - `test_storage_integration.py` / `test_storage_integration_fixed.py` — tests paramétrés multi-backend
- **Tests paramétrés** (`@pytest.mark.parametrize`) : le même jeu de tests s'exécute contre `InMemoryStorage` **et** `SQLiteStorage`, garantissant la substitutabilité exacte (principe de Liskov)
- **Zero régression** : 100 % de passage sur les deux backends, y compris cas limites (entité introuvable, double sauvegarde, suppression idempotente)
