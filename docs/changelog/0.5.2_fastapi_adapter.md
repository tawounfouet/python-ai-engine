## Vue d'ensemble

`0.5.2` livre le **deuxième adaptateur de Phase 5** : un ensemble de routers
[FastAPI](https://fastapi.tiangolo.com/) montables dans n'importe quelle
application existante.

L'adaptateur expose l'intégralité de `ai_engine` via une API REST typée,
documentée automatiquement (OpenAPI / Swagger UI), et compatible SSE pour
le streaming.

Il est installé comme extra optionnel (`pip install ai-engine[fastapi]`) et
conçu pour être intégré en quelques lignes :

```python
from fastapi import FastAPI
from ai_engine.adapters.fastapi import create_router

app = FastAPI()
app.include_router(create_router("app.db"), prefix="/api")
```

Prochaine étape de la série 0.5.x :
- `0.5.3` → Django adapter (`src/ai_engine/adapters/django/`)

### `src/ai_engine/services/agent.py`

**Bugfix** : `AgentService.create_agent()` utilisait `kwargs.get("slug", ...)` puis
passait `**kwargs` (qui contenait encore `slug`) à `Agent(...)`, causant
`TypeError: Agent() got multiple values for keyword argument 'slug'`.

Correction : `slug` est maintenant extrait avec `kwargs.pop()` avant l'appel à
`Agent()`, et `None` est traité comme "non fourni" (dérivé du `name`).

```python
# Avant (buggy)
agent = Agent(
    ...
    slug=kwargs.get("slug", name.lower().replace(" ", "-")),
    **kwargs,   # ← slug toujours présent → TypeError
)

# Après (corrigé)
_slug_raw = kwargs.pop("slug", None)
slug = _slug_raw if _slug_raw is not None else name.lower().replace(" ", "-")
agent = Agent(..., slug=slug, **kwargs)
```

## API REST exposée

### Endpoints

| Méthode | Path | Description |
|---------|------|-------------|
| `GET` | `/providers` | Liste paginée des providers |
| `POST` | `/providers` | Créer un provider |
| `GET` | `/providers/{id}` | Détail d'un provider |
| `PATCH` | `/providers/{id}` | Mise à jour partielle |
| `DELETE` | `/providers/{id}` | Suppression |
| `GET` | `/agents` | Liste paginée des agents |
| `POST` | `/agents` | Créer un agent |
| `GET` | `/agents/{id}` | Détail (par ID ou slug) |
| `PATCH` | `/agents/{id}` | Mise à jour partielle |
| `DELETE` | `/agents/{id}` | Suppression |
| `GET` | `/conversations` | Liste (filtrable par `agent_id`) |
| `POST` | `/conversations` | Démarrer une conversation |
| `GET` | `/conversations/{id}` | Détail |
| `DELETE` | `/conversations/{id}` | Suppression |
| `GET` | `/conversations/{id}/messages` | Historique des messages |
| `POST` | `/chat` | Chat synchrone (renvoie la réponse complète) |
| `POST` | `/chat/stream` | Chat en streaming (SSE — `text/event-stream`) |

### Sécurité des données

- Le champ `api_key` n'est **jamais** retourné dans les réponses `ProviderResponse`.
- À la place : `has_api_key: bool` indique si une clé est configurée.

### Quick Start complet

```python
from fastapi import FastAPI
from ai_engine.adapters.fastapi import create_router
from ai_engine.adapters.fastapi.exception_handlers import register_handlers

app = FastAPI(title="My AI App")
register_handlers(app)               # domain exceptions → HTTP 404/500
app.include_router(
    create_router("my_app.db"),
    prefix="/api",
)

# uvicorn my_app:app --reload
```

```bash
# Tester l'API
curl http://localhost:8000/api/providers
curl -X POST http://localhost:8000/api/agents \
     -H "Content-Type: application/json" \
     -d '{"name":"Bot","provider_id":"<id>","system_prompt":"Tu es un assistant."}'

# Chat
curl -X POST http://localhost:8000/api/chat \
     -H "Content-Type: application/json" \
     -d '{"agent_id":"<id>","message":"Bonjour !"}'

# Chat streaming (SSE)
curl -N -X POST http://localhost:8000/api/chat/stream \
     -H "Content-Type: application/json" \
     -d '{"agent_id":"<id>","message":"Raconte-moi une histoire."}'
```

## Architecture de la couche FastAPI

```
adapters/fastapi/
├── __init__.py            create_router() — point d'entrée public
├── schemas.py             Pydantic I/O schemas (Request + Response)
├── dependencies.py        FastAPI Depends() : get_storage, get_agent_service, Pagination
├── exception_handlers.py  register_handlers(app)
└── routers/
    ├── providers.py       GET/POST/PATCH/DELETE /providers
    ├── agents.py          GET/POST/PATCH/DELETE /agents
    ├── conversations.py   GET/POST/DELETE /conversations + /messages
    └── chat.py            POST /chat  +  POST /chat/stream (SSE)
```

**Principes de conception :**
- `get_storage` est un **générateur** (`yield`) pour supporter cleanup futur
- La dépendance `storage` est injectée via `app.dependency_overrides[get_storage]` (pattern officiel FastAPI) — aucune variable globale
- `POST /chat/stream` utilise `asyncio.get_event_loop().run_in_executor()` pour exécuter `svc.chat()` (synchrone) sans bloquer l'event loop
- Les routers acceptent ID complet **ou** slug pour agents/conversations (résolution transparente)
- `PaginatedResponse` générique : `total`, `limit`, `offset`, `items`
