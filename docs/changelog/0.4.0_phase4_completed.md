# Changelog - Version 0.4.0 (Phase 4 : Tool System, Skills & EventBus)

**Date** : Mars 2026

## Vue d'ensemble

Phase 4 complète le cœur de l'orchestration active du moteur : les **Tools** concrets et leur classe de base abstraite, le **système de Skills** (capacités de haut niveau), et l'**EventBus** pour le découplage interne par événements. Ces trois systèmes sont pleinement intégrés et exposés dans l'API publique du package.

---

## Ajouts ✨

### 🛠 Système de Tools (`src/ai_engine/tools/`)

- **`BaseTool` ABC** (`tools/base.py`) — Classe de base abstraite pour tous les tools concrets :
  - Attributs de classe déclaratifs : `key`, `name`, `description`, `tool_type`, `parameters_schema`, `requires_approval`, `is_dangerous`, `is_active`
  - `__init_subclass__` applique la règle "clé non vide" à la définition de classe (fail-fast)
  - Méthode `run(**kwargs)` abstraite (synchrone, obligatoire)
  - Méthode `arun(**kwargs)` avec fallback automatique sur `asyncio.to_thread(run)` si non surchargée
  - Propriété `.definition` → instance `ToolDefinition` Pydantic générée automatiquement
  - Méthode `.get_function_schema()` → dict OpenAI/Anthropic function-calling format
  - `__call__(**kwargs)` délègue à `run()` pour une syntaxe naturelle `tool(...)`

- **`CalculatorTool`** (`tools/calculator.py`) — Évaluateur d'expressions mathématiques sécurisé :
  - Sandbox eval avec liste d'autorisation explicite (opérateurs `ast` + fonctions `math` uniquement)
  - Aucun accès aux builtins, aucune possibilité d'injection de code
  - Retourne le résultat numérique ou un message d'erreur explicite

- **`DuckDuckGoSearchTool`** (`tools/web_search.py`) — Recherche web sans clé API :
  - Utilise `duckduckgo_search` (DDGS) ; dépendance optionnelle avec `MissingDependencyError` clair
  - Paramètres : `query`, `max_results` (défaut : 5)
  - Retourne une liste de résultats `{title, url, snippet}` sérialisée JSON

- **`SerperSearchTool`** (`tools/web_search.py`) — Recherche Google via l'API Serper :
  - Paramètre `api_key` injecté à l'instanciation (ou `SERPER_API_KEY` via env)
  - Retourne les résultats organiques Google sérialisés JSON
  - Nécessite `requests` (dépendance optionnelle)

- **`HttpGetTool`** / **`HttpPostTool`** (`tools/http_client.py`) — Clients HTTP génériques :
  - `HttpGetTool` : GET avec paramètres `url` + `headers` (dict optionnel)
  - `HttpPostTool` : POST avec paramètres `url`, `payload` (dict), `headers`
  - Timeout configurable à l'instanciation (défaut : 10 s) ; retourne le corps de réponse en chaîne
  - Nécessite `httpx` (dépendance optionnelle)

- **`tools/__init__.py`** mis à jour : exporte `BaseTool`, `CalculatorTool`, `DuckDuckGoSearchTool`, `SerperSearchTool`, `HttpGetTool`, `HttpPostTool` en plus des `ToolRegistry` et `ToolExecutor` existants.

### 📡 Système d'Événements (`src/ai_engine/events/`)

- **`BaseEvent`** (`events/events.py`) — Modèle Pydantic de base pour tous les événements :
  - Champs communs : `event_id` (UUID auto), `event_type` (`EventType`), `timestamp` (UTC auto), `metadata` (dict libre)

- **20 classes d'événements typées** couvrant tous les cycles de vie :
  - Agents : `AgentCreatedEvent`, `AgentUpdatedEvent`, `AgentDeletedEvent`
  - Conversations : `ConversationStartedEvent`, `ConversationEndedEvent`
  - Messages : `MessageSentEvent`, `MessageReceivedEvent`
  - Tools : `ToolCalledEvent`, `ToolSucceededEvent`, `ToolFailedEvent`
  - LLM : `LLMRequestStartedEvent`, `LLMRequestCompletedEvent`, `LLMRequestFailedEvent`
  - Skills : `SkillStartedEvent`, `SkillCompletedEvent`, `SkillFailedEvent`
  - Exécutions : `ExecutionStartedEvent`, `ExecutionCompletedEvent`, `ExecutionFailedEvent`
  - Générique : `CustomEvent`

- **`EventBus`** (`events/bus.py`) — Bus central thread-safe :
  - Inscription de handlers **sync et async** via `@bus.on(EventType.XYZ)` ou `bus.subscribe()`
  - Listeners **wildcard** (`"*"`) : reçoivent tous les événements quel que soit leur type
  - **Middleware** : chaîne de callables `(event) → event` exécutés avant chaque dispatch
  - Émission **synchrone** (`bus.emit()`) et **asynchrone** (`await bus.aemit()`)
  - **Isolation des erreurs** : un handler en échec n'interrompt pas les autres handlers (loggué)
  - Flag `raise_on_handler_error=True` pour lever les erreurs en mode test
  - `bus.clear()` : réinitialisation des subscriptions et middlewares
  - `bus.handler_count(event_type)` : introspection du nombre de handlers enregistrés

- **Singleton global** : `get_event_bus()` retourne (ou crée) l'instance globale partagée ; `reset_event_bus()` la réinitialise (utile dans les tests).

- **`events/__init__.py`** : expose l'intégralité de l'API publique événementielle.

### 🧩 Système de Skills (`src/ai_engine/skills/`)

- **`BaseSkill` ABC** (`skills/base.py`) — Classe de base abstraite pour les Skills :
  - Attributs de classe déclaratifs : `key`, `name`, `description`, `category`, `required_tool_keys`, `is_active`
  - `__init_subclass__` applique la règle "clé non vide" (fail-fast, cohérent avec `BaseTool`)
  - Accepte un `EventBus` optionnel à l'instanciation (`inject_event_bus()`)
  - `run(**kwargs)` abstraite (synchrone), `arun(**kwargs)` avec fallback `asyncio.to_thread`
  - `execute(**kwargs)` / `aexecute(**kwargs)` — wrappers publics avec émission automatique d'événements `SkillStarted` → `SkillCompleted` / `SkillFailed` et mesure de durée (`duration_ms`)
  - Propriété `.definition` → instance `Skill` Pydantic

- **`SkillRegistry`** (`skills/registry.py`) — Registre de skills :
  - `register(skill)` : enregistre une instance `BaseSkill` (erreur si clé dupliquée)
  - `get(key)` : récupère un skill par clé (`SkillNotFoundError` si absent)
  - `list(category=None)` : liste tous les skills (filtrable par `SkillCategory`)
  - `unregister(key)` : retire un skill du registre
  - `can_execute(key, available_tool_keys)` : valide que tous les `required_tool_keys` du skill sont disponibles
  - `inject_event_bus(bus)` : propage l'`EventBus` à tous les skills enregistrés (et futurs)
  - `count` : propriété indiquant le nombre de skills inscrits

- **`skills/__init__.py`** : expose `BaseSkill` et `SkillRegistry`.
