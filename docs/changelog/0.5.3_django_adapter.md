## Vue d'ensemble

`0.5.3` livre le **troisième adaptateur de Phase 5** : une intégration Django
complète avec [Django REST Framework](https://www.django-rest-framework.org/)
et un backend de stockage `DjangoORMStorage` qui utilise l'ORM Django à la
place de SQLite brut.

L'adaptateur est installé comme extra optionnel
(`pip install ai-engine[django]`) et s'intègre en quelques lignes :

```python
# settings.py
INSTALLED_APPS = [
    ...
    "ai_engine.adapters.django",
]

# urls.py
from ai_engine.adapters.django.urls import urlpatterns as ai_urls
urlpatterns += ai_urls
```

Les tables sont créées via les migrations Django standard :

```bash
python manage.py migrate
```

## Architecture `DjangoORMStorage`

### Stratégie de stockage

Chaque modèle ORM combine :
- **colonnes d'index** : `provider_id`, `agent_id`, `slug`, `is_active`, etc. (filtrables via l'ORM)
- **`data = JSONField()`** : sérialisation complète du modèle Pydantic

Cette approche évite la duplication de schéma tout en gardant des requêtes
efficaces sur les colonnes critiques.

### Modèles ORM

```
ProviderRecord       → table ai_engine_providers
AgentRecord          → table ai_engine_agents      (slug unique)
ConversationRecord   → table ai_engine_conversations
MessageRecord        → table ai_engine_messages
```

Tous les modèles utilisent `app_label = "ai_engine"` dans leur `Meta`.

### Méthodes implémentées

Providers :
- `save_provider`, `get_provider`, `get_default_provider`, `list_providers`, `delete_provider`

Agents :
- `save_agent`, `get_agent`, `get_agent_by_slug`, `list_agents`, `delete_agent`

Conversations :
- `save_conversation`, `get_conversation`, `list_conversations`, `delete_conversation`

Messages :
- `save_message`, `get_messages`

Les domaines Tools, Skills, Executions, Graphs, Memory, Knowledge sont stubés
(retournent `None` / `[]`) — prêts pour une implémentation future.

## Setup tests (sans projet Django)

Le `conftest.py` configure Django en mémoire via `pytest_configure` :

```python
settings.configure(
    DATABASES={"default": {"ENGINE": "django.db.backends.sqlite3", "NAME": ":memory:"}},
    INSTALLED_APPS=["django.contrib.contenttypes", "django.contrib.auth", "ai_engine.adapters.django"],
    ...
)
```

Et surcharge `django_db_setup` pour créer les tables directement via
`schema_editor.create_model()` — pas besoin de dossier `migrations/`.

## Utilisation

```python
# settings.py
INSTALLED_APPS = [
    "django.contrib.contenttypes",
    "django.contrib.auth",
    "rest_framework",
    "ai_engine.adapters.django",
]

AI_ENGINE = {
    "EVENT_BUS_ENABLED": True,   # active les signaux Django ↔ EventBus
}

# urls.py
from django.urls import path, include
from ai_engine.adapters.django.urls import urlpatterns as ai_urls

urlpatterns = [
    path("api/ai/", include(ai_urls)),
]
```

Après `python manage.py migrate`, les endpoints sont disponibles :

| Méthode | URL | Description |
|---------|-----|-------------|
| GET | `/api/ai/providers/` | Lister les providers |
| POST | `/api/ai/providers/` | Créer un provider |
| GET | `/api/ai/providers/{id}/` | Détail provider |
| PATCH | `/api/ai/providers/{id}/` | Mettre à jour |
| DELETE | `/api/ai/providers/{id}/` | Supprimer |
| GET | `/api/ai/agents/` | Lister les agents |
| POST | `/api/ai/agents/` | Créer un agent |
| GET | `/api/ai/agents/{id}/` | Détail agent (id ou slug) |
| PATCH | `/api/ai/agents/{id}/` | Mettre à jour |
| DELETE | `/api/ai/agents/{id}/` | Supprimer |
| GET | `/api/ai/conversations/` | Lister les conversations |
| POST | `/api/ai/conversations/` | Créer une conversation |
| GET | `/api/ai/conversations/{id}/` | Détail conversation |
| GET | `/api/ai/conversations/{id}/messages/` | Messages d'une conversation |
| DELETE | `/api/ai/conversations/{id}/` | Supprimer |
| POST | `/api/ai/chat/` | Envoyer un message (chat) |
