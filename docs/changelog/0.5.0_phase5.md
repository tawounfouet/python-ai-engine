# Changelog - Version 0.5.0 (Phase 5 : Logging, Intégrations & Configuration Env)

**Date** : Avril 2026

## Vue d'ensemble

Phase 5 apporte trois dimensions complémentaires au moteur : un **système de logging structuré** prêt pour la production, l'**intégration de connecteurs externes** via `pyconnectors`, et une **configuration d'environnement** exhaustive. Les exemples 06 à 08 illustrent ces trois couches combinées dans des pipelines réels. Plusieurs exemples existants ont également été sécurisés (suppression des clés API exposées en clair).

## Ajouts ✨

### 📋 Système de Logging (`src/ai_engine/logging/`)

Module de logging structuré, pensé pour être utilisable en développement (couleurs ANSI lisibles) comme en production (NDJSON consommable par Loki, Datadog, etc.).

- **`StructuredFormatter`** — Formatter TTY-aware pour la sortie console :
  - Lazily évalue la propriété `_colorize` : active les couleurs ANSI uniquement si le stream cible est un vrai TTY (`isatty()`)
  - Palette de couleurs par niveau : `DEBUG` (cyan), `INFO` (vert), `WARNING` (jaune), `ERROR` (rouge), `CRITICAL` (rouge gras)
  - Format incluant timestamp ISO-8601, niveau, logger name et message

- **`JSONFormatter`** — Formatter NDJSON pour fichiers et collecteurs de logs :
  - Chaque ligne est un objet JSON autonome (newline-delimited JSON)
  - Champs : `timestamp`, `level`, `logger`, `message`, plus tous les champs `extra` passés à l'appel de log
  - Sérialisation correcte des exceptions (`exc_info`) en string

- **`LoggingConfig`** — Dataclass immuable de configuration du logging :
  - Champs : `level` (`str`, défaut `"INFO"`), `format` (`"structured"` | `"json"`), `enable_queue` (`bool`), `log_file` (`str | None`), `json_file` (`str | None`), `capture_warnings` (`bool`), `propagate` (`bool`)
  - Méthode `with_overrides(**kwargs) → LoggingConfig` : retourne une nouvelle instance avec les champs overridés (immutabilité préservée)

- **`configure_logging(config: LoggingConfig | None)`** — Point d'entrée unique de configuration :
  - Configure le root logger ou le logger `ai_engine` selon la config fournie
  - Attache `StructuredFormatter` (console) et/ou `JSONFormatter` (fichier) selon les paramètres
  - Active le `QueueHandler` asyncio si `enable_queue=True`
  - Redirige `warnings.warn` vers le logging si `capture_warnings=True`

- **`get_logger(name: str) → logging.Logger`** — Factory de loggers nommés :
  - Convention de nommage automatique : `ai_engine.<name>`

- **`logged_operation(name, logger, level, **extra)`** — Context manager de traçage d'opérations :
  - Loggue le début (`"Starting <name>"`) et la fin (`"Completed <name>"`, avec `duration_ms`)
  - En cas d'exception : loggue `"Failed <name>"` avec le traceback et reraise

- **`QueueHandler` async** (activé via `enable_queue=True`) :
  - Découple l'émission des logs du I/O en déléguant l'écriture dans un thread séparé via `logging.handlers.QueueHandler` + `QueueListener`
  - Évite les blocages sur les handlers lents (fichiers, réseau)

### 🔌 Adaptateurs optionnels (`src/ai_engine/adapters/`)

- **`adapters/structlog/`** — Bridge `structlog` → `stdlib logging` :
  - Permet d'utiliser `structlog` comme frontend tout en routant les événements vers les handlers `stdlib` configurés par `configure_logging()`
  - Compatible avec les collecteurs qui s'appuient sur l'écosystème `logging` standard

- **`adapters/snowflake/`** — Handler Snowflake (WIP) :
  - `SnowflakeHandler` : handler `logging.Handler` personnalisé envoyant les enregistrements de log vers une table Snowflake
  - Statut actuel : work-in-progress, fonctionnalité de base opérationnelle, non exposée dans l'API publique principale

### 📦 Intégration pyconnectors (`examples/06_pyconnectors_integration.py`)

- Démonstration de l'intégration du package externe `pyconnectors` dans le pipeline `ai_engine`
- Concepts illustrés : `ConnectorFactory`, `Registry` des connecteurs, hooks de cycle de vie
- Le package `pyconnectors` est déclaré en mode **editable** dans `pyproject.toml` (`-e path/to/pyconnectors`) avec entrée miroir dans `uv.lock`

### 🌍 Configuration d'environnement (`.env.example`)

- Référence exhaustive de **toutes les variables d'environnement** reconnues par le moteur :
  - Clés API : `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GROQ_API_KEY`, `SERPER_API_KEY`
  - Logging : `AI_ENGINE_LOG_LEVEL`, `AI_ENGINE_LOG_FORMAT`, `AI_ENGINE_LOG_FILE`
  - Storage : `AI_ENGINE_DEFAULT_STORAGE`, `AI_ENGINE_SQLITE_DB_PATH`, `AI_ENGINE_JSON_STORAGE_PATH`
  - Divers : `AI_ENGINE_DEBUG`, `AI_ENGINE_DEFAULT_PROVIDER_TYPE`, `AI_ENGINE_DEFAULT_MODEL`
